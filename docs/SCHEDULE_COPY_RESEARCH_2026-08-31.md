> **목표**: 월별 스케쥴 + 일별 근무설정 · 효과적 구현 방법
> **참고**: Deputy · When I Work · Sling · Shiftboard · Homebase · Linear (버전 관리 톤)
> **모드**: 리서치·설계 제안 · 사용자 승인 후 구현

## 1. 현재 시스템 분석

### 테이블 3종 (이미 존재)
| 테이블 | 용도 | PK | 활용도 |
|---|---|---|---|
| `schedules` | 직원별 일자별 근무 유형 (오픈/마감/휴무) | (empId, date) | ✅ 완전 사용 |
| `zone_day_assignments` | 날짜별 구역·점심·휴게 배정 (JSONB) | date | ✅ 완전 사용 |
| `zone_dow_templates` | **요일별 배정 템플릿 (dow 0~6)** | dow | ⚠️ 저활용 · 전월복사에서 미사용 |

### 현재 전월복사 로직
| 대상 | 매칭 방식 | 상세 |
|---|---|---|
| schedules | **weekday majority vote** | empId → dow → 최다 등장 type |
| zone_day_assignments | **day-of-month 그대로** | 8/15 → 9/15 |

### 문제점
1. **일관성 부재** · 두 시스템이 서로 다른 기준
2. **템플릿 인프라 낭비** · zone_dow_templates 존재하지만 전월복사에서 무시
3. **선택권 없음** · 사용자가 방식 선택 불가
4. **미리보기 없음** · 덮어쓰기 후 확인만 · 사전 diff 없음
5. **부분 복사 불가** · 특정 직원·특정 주만 복사 옵션 없음

## 2. 업계 표준 · 최신 트렌드 (2024-2026)

### A. **템플릿 우선 아키텍처** (Deputy · When I Work · Sling)
> "Copy from template" 이 최고 UX

- **재사용 가능한 shift template** 저장 · 반복 사용
- 월별 뷰에서 "Apply template to this month" 원클릭
- 템플릿은 요일 기반 · 월별 기반 · 롤링 기반 3종
- **우리 시스템 준비도**: 90% · zone_dow_templates 있음 · UI 만 추가

### B. **Duplicate with Preview** (Linear · Notion 톤)
> 변경 사항 미리보기 후 확정

- "Copy previous month" 클릭 → 미리보기 diff 표시
- 사용자 · 개별 항목 취사선택 (`X` 로 제외 · 재수정)
- [Apply] 버튼으로 확정
- **핵심**: 실행 전에 결과 검증

### C. **다층 복사 옵션** (Shiftboard · Homebase)
> 복사 스코프 세분화

```
□ 전체 월 복사
  ├─ □ 월별 스케쥴 (근무 유형)
  │   ├─ 매칭 방식 · [○ 요일 기준] [○ 일자 기준] [○ 롤링 4주]
  │   └─ 스코프 · [○ 전체 직원] [○ 선택 직원 …]
  └─ □ 일별 근무 배치 (구역/점심/휴게)
      ├─ 매칭 방식 · [○ 요일 기준] [○ 일자 기준] [○ 템플릿 적용]
      └─ 스코프 · [○ 전체 배정] [○ 구역만] [○ 점심/휴게만]
```

### D. **AI 제안 · 컨플릭트 감지** (Rippling · Workday)
> 자동 채움 + 리뷰

- 이번달 신규 데이터 감지 · "8월과 다른 패턴 감지 · 유지 여부?"
- 퇴사자 자동 제외 · "김철수님 퇴사 · 배정에서 제외됨 (3건)"
- 공휴일 자동 처리 · "9/29 추석 · 배정 비움? 특별 배치?"

### E. **버전 컨트롤 · 롤백** (Linear inspired)
> 실수해도 즉시 복구

- 매 복사 · 스냅샷 저장 (schedule_snapshots 테이블)
- "복구" 버튼 · 이전 상태로 롤백
- 감사 이력 · 누가 언제 무엇을 변경

### F. **하이브리드 매칭** (best-of-both)
> 요일 + 일자 · 상황에 맞게

- **1순위**: 요일 매칭 (반복적 근무 패턴)
- **2순위**: 일자 매칭 (특별한 날 · 공휴일)
- **3순위**: 사용자 지정 (수동 조정)
- 예 · 요일 매칭 우선 · 하지만 9/29 (추석) 은 특별 date 로 override

## 3. 추천 아키텍처 (Phase 1~4)

### Phase 1 · **템플릿 우선 활용** (즉시 · 저리스크)
- `zone_dow_templates` 활용 확대
- 전월복사 · 옵션 추가:
  - `[○ 요일 템플릿 적용]` · 기본
  - `[○ 전월 데이터 복사]` · 기존
- 매월 자동 · 확정 시 → 요일 템플릿 upsert
- **UI**: 라디오 버튼 · 사용자 선택

### Phase 2 · **다이나믹 프리뷰** (medium · 사용자 승인 필수)
- "복사 미리보기" 카드 · diff 표시
  - 신규 · 초록 배지
  - 변경 · 노랑 배지 (기존값 → 새값)
  - 삭제 · 빨강 배지 (전월 있고 이번달 없음)
- 개별 항목 · 체크박스 · 취사선택
- [적용] 버튼으로 확정

### Phase 3 · **컨플릭트 감지·리조리티드** (medium)
- 퇴사자 감지 · 배정에서 자동 제외 · 알림
- 공휴일 · Google Calendar API 연동 · 특별 처리 선택
- 근무 시간 초과 감지 · "이번달 김철수 220h · 초과"

### Phase 4 · **버전 컨트롤·롤백** (large)
- `schedule_snapshots` · 매 복사 스냅샷
- "복구" UI · 최근 N개 롤백
- 감사 이력 (who · when · what)

## 6. 리스크 · 회귀 위험

| 항목 | 리스크 | 대응 |
|---|---|---|
| 기존 사용자 workflow | 라디오 기본값이 새 방식이면 혼란 | 기본값 = 기존 동작 유지 |
| 요일 매칭 · 회차별 로테이션 잃음 | 5개 월요일 중 1개만 반영 | 옵션으로만 · 기본 아님 |
| 템플릿 우선 · 이번달 특별 배치 사라짐 | 템플릿이 date-specific 을 override | 프리뷰 필수 · 개별 취사선택 |
| 스냅샷 저장 · DB 용량 | 매 복사 = 스냅샷 · 6개월 후 크기 부담 | 3개월 이상 자동 삭제 · rotate |
